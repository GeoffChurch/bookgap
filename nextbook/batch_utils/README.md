# OpenAI Batch Processing for Textbook Proposals

This module contains utilities for processing gap analysis prompts using OpenAI's Batch API to generate textbook proposals.

## Files

- `batch_operations.py` - Core batch processing functionality
- `send_prompts_to_openai.py` - Script to submit all prompts to OpenAI Batch API
- `check_batch_status.py` - Interactive script to check batch job status and download results  
- `extract_all_batch_results.py` - Script to extract proposals from existing batch results files
- `__init__.py` - Package initialization exposing public API
- `README.md` - This documentation file

## Setup

1. Set your OpenAI API key:
   ```bash
   export OPENAI_API_KEY="your-api-key-here"
   ```

2. Ensure you have prompt files generated by running:
   ```bash
   python -m nextbook.gap_finder
   ```

## Usage

### Step 1: Submit Batch Job

Run the main batch processing script:
```bash
python -m nextbook.batch_utils.send_prompts_to_openai
```

This script will:
- Find all `*_prompt.txt` files in `artifacts/gaps/`
- Create a batch request file in JSONL format
- Upload the file to OpenAI
- Submit a batch job
- Monitor the job until completion
- Download and process results when done

The script expects prompt files to be organized as:
```
artifacts/gaps/
├── NONE_k=0_radiusfrac=0.75/
│   ├── gap_0/
│   │   ├── AI_topic_gap_0_prompt.txt
│   │   └── ...
│   └── gap_1/
│       └── ...
```

The script will show a cost estimate before proceeding and ask for confirmation.

### Step 2: Check Status (Optional)

If you need to check the status of batch jobs or download results separately:
```bash
python -m nextbook.batch_utils.check_batch_status
```

This interactive script allows you to:
- List all your batch jobs
- Check the status of a specific batch job
- Download results for completed batch jobs
- Monitor batch jobs until completion

### Step 3: Extract Results (Optional)

To extract proposals from existing batch results files:
```bash
# Extract from all results files
python -m nextbook.batch_utils.extract_all_batch_results

# Extract from specific file
python -m nextbook.batch_utils.extract_all_batch_results results_batch_12345.jsonl

# Extract from pattern
python -m nextbook.batch_utils.extract_all_batch_results "results_batch_*.jsonl"

# Extract with gap index subdirectories (organizes by gap_0/, gap_1/, etc.)
python -m nextbook.batch_utils.extract_all_batch_results --split-by-gap-idx
```

## Output

Results are saved in `artifacts/batch_results/batch_[BATCH_ID]/textbook_proposals/` with the following structure:
```
artifacts/batch_results/
├── batch_68904c48b88c8190bcbd8e8e86aca696/
│   └── textbook_proposals/
│       └── NONE_k=0_radiusfrac=0.75/
│           ├── AI_and_Multimedia_in_Education_gap_0_proposal.tex
│           ├── AI_in_cancer_detection_gap_0_proposal.tex
│           └── ...
└── batch_1754287174/
    └── textbook_proposals/
        └── [other_configurations]/
```

When using `--split-by-gap-idx`, proposals are organized with additional gap subdirectories:
```
artifacts/batch_results/
├── batch_68904c48b88c8190bcbd8e8e86aca696/
│   └── textbook_proposals/
│       └── NONE_k=0_radiusfrac=0.75/
│           ├── gap_0/
│           │   ├── AI_and_Multimedia_in_Education_gap_0_proposal.tex
│           │   ├── AI_in_cancer_detection_gap_0_proposal.tex
│           │   ├── all.tex              # Local includes (same directory)
│           │   ├── all_with_path.tex    # Includes with gap_0/ paths
│           │   ├── standalone.tex       # Complete standalone document
│           │   └── ...
│           └── gap_1/
│               ├── Another_topic_gap_1_proposal.tex
│               ├── all.tex              # Local includes
│               ├── all_with_path.tex    # Includes with gap_1/ paths
│               ├── standalone.tex       # Complete standalone document
│               └── ...
```

Each gap subdirectory contains three compilation files:
- **`all.tex`**: Local includes using just filenames, for use when the file is in the same directory as the proposals
- **`all_with_path.tex`**: Includes with `gap_X/` path prefixes, for including from parent directories with `\input{gap_0/all_with_path}`
- **`standalone.tex`**: Complete LaTeX document that can be compiled directly with `pdflatex standalone.tex`

All files organize proposals with each proposal on a separate page using `\clearpage` commands.

**Usage examples:**
- Copy the entire `gap_0/` directory to your LaTeX project and use `\input{all}` from within that directory
- Keep the gap directories in place and use `\input{gap_0/all_with_path}` from the parent directory
- Compile `standalone.tex` directly for a complete PDF

Each proposal file contains LaTeX-formatted textbook proposals that can be directly included in academic papers.

## Direct Python Usage

You can also use the batch utilities directly in Python:

```python
from nextbook.batch_utils import (
    monitor_batch_job,
    download_batch_results,
    extract_textbook_proposals,
    process_completed_batch,
    BATCH_DIR
)

# Example: Process a completed batch
stats = process_completed_batch("batch_12345")
if stats:
    print(f"Extracted {stats['successful_count']} proposals")
```

## Pricing

The script uses GPT-4.1 with batch processing, which provides:
- 50% discount on API calls
- Estimated cost: ~$0.03-0.05 per proposal
- Total estimated cost for all prompts: ~$5-15 (depending on number of gaps)

## Batch API Features

- **Asynchronous processing**: Submit large batches without waiting
- **Cost savings**: 50% discount compared to synchronous API calls
- **High throughput**: Process thousands of requests efficiently
- **24-hour completion window**: Batches complete within 24 hours

## Error Handling

The scripts handle various error conditions:
- Failed API requests are logged and saved separately
- Network interruptions during monitoring
- Invalid or corrupted prompt files
- Missing API keys

## Monitoring

Batch jobs can be monitored through:
- The script's built-in monitoring (polls every 30 seconds)
- OpenAI's web dashboard
- The `check_batch_status.py` script
